## The problem

- Every session with a coding agent starts from nothing. Close the window and the next
  session has no idea what was just decided.
- It is not only mine: in [claude-code#39961](https://github.com/anthropics/claude-code/issues/39961)
  a user reports losing 50–75% of session time to redoing work.

## The approach

- The project keeps a one-line pointer; the memory lives in a markdown vault the owner
  already has, in files that open, diff and delete without the tool.
- No MCP server, nothing hosted, no vector database, no background process.

## The tradeoffs

- **Simple over automatic.** Injecting context automatically at every session start was
  rejected for a one-line reminder that never guesses what is relevant.
- **Repositioned by built-in memory.** Claude Code and Cursor now ship their own memory, which
  made "give your agent memory" worthless as a pitch. What they can't do is follow you to
  another agent or another machine — that became the pitch.
- **Files over a database.** Readable and portable without the tool, at the cost of queries.

## What I would do differently

- The first six weeks went unrecorded: the tool couldn't record its own build until it could
  write session summaries.
