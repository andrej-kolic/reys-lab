## The problem

A coding agent starts every session from nothing. Close the window and the next session has
no idea what was decided an hour ago, what was tried, or why an approach was dropped. That
context lived in chat transcripts I would never open again.

I wasn't the only one losing it. In
[claude-code#39961](https://github.com/anthropics/claude-code/issues/39961) a user reports
spending 50–75% of their session time redoing work across sessions.

## The approach

The project gets a two-line `.grounder.json` pointing at a folder in a markdown vault I
already keep. Plans, notes and session summaries are plain files in that folder, so they
open, diff and delete without Grounder installed. A handful of agent commands read and write
them — only when asked.

There is no MCP server, nothing hosted, no vector database and no background process. Those
were cut on purpose: reading and writing vault files is a solved problem with plenty of
tools already; the missing part was an opinionated workflow on top of it.

## The tradeoffs

**Simple over automatic.** The obvious feature is loading the last session into every new
one automatically. I rejected it: any rule for what's relevant guesses wrong often enough to
be confusing, and silent context injection is a complaint people already had about other
tools. What shipped is one line at session start — the newest summary's title and date —
which never blocks and is easy to ignore.

**Repositioned by built-in memory.** A month in, a check of the competition found Claude Code
and Cursor both ship their own memory, on by default. "Give your agent memory" stopped being worth saying. What
built-in memory can't do is follow you to a different agent or a different machine, and a
folder of markdown can — so that became the pitch.

**Files over a database.** Plain files are readable, portable and survive the tool going
away. The cost is search: it walks the files and matches keywords every time, with no index
and no semantic matching.

## What I would do differently

Record from day one. The session summaries only start six weeks after the first commit,
because the tool couldn't record its own build until it could write them — so the earliest
decisions are the least documented ones.
